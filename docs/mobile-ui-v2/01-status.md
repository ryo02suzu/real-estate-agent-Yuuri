## 3. 低ズームの地図タイルについて
- 国土地理院の淡色・標準が z4 以下を配信しているかは、開発環境の外部通信（`curl` / `WebFetch` / `git fetch`）が承認されず**確認できなかった**。既存の PC の地図（`lib/map-style.ts`）は淡色・標準を z5 以上としている。
- そこで実行時に確かめる設計にした（`lib/japan-basemap.ts`）：地図を作ったら、東京付近の z4 のタイル（淡色・標準）が読めるかを1回確かめ、
  - 淡色が読める → そのまま。
  - 淡色は読めず標準が読める → 標準地図を低ズーム（地図ズーム4未満）の下敷きにする。
  - どちらも読めない → 北海道〜九州だけを、読むタイルが z5 以上になる範囲（地図の最小ズーム4）で見せる。
  - いずれもタイルの無い所は薄い青緑の面（白くならない）。通信エラーだけが続くときは「地図を表示できませんでした。住所を入力して調べられます。」を出し、入力は使える。
- 地図の最小ズームは3（MapLibre の 256px ラスタは「ズーム＋1」の段を読むので、読むタイルは z4 以上だけ）。
- **確認方法（ネットにつながる環境で）**：`npm run check-tiles`（淡色・標準の z2〜z5 を実際に取得して、状態・CORS をログに出す。z5 以上が読めないと失敗する）。またはブラウザで Preview を開き、日本全体の地図が出るか見る。

## 5. `.claude-pr/` による lint の失敗
- 原因：Claude の実行環境（claude-code-action）が、作業ディレクトリの直下に PR 側の `.claude` の控えを `.claude-pr/` として置く（`.git/info/exclude` に `/.claude-pr/` があり、git では追跡されない）。中に外部 Agent Skills のサンプル（`.claude-pr/.claude/skills/**` の `.tsx`・`.js`）があり、`.claude/skills/**` だけを除外していた ESLint の設定では、`no-explicit-any`・`no-require-imports` で失敗した。
- CI（`.github/workflows/ci.yml`）と Vercel は新しく取得したリポジトリで動くので `.claude-pr/` は無く、影響しない。
- 対応：`eslint.config.mjs` の `globalIgnores` に `.claude-pr/**` を追加（アプリのコードは対象のまま）。
