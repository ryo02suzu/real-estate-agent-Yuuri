# PC のオープニング第4版：制作計画

第2版（`scripts/pc-opening`。日本列島 → 北アルプスへ降りる → 上高地を鷹の目で飛ぶ → 雲海と朝日 → 白鳥 → ロゴ）の流れを土台に、
画質・本物らしさ・飛び方を作り直す。第3版（`scripts/pc-opening3`）の森の仕組みと、赤富士の試し（`scripts/gpu-render`）の雲の仕組みも使う。
この計画が、手分けして作る人（手伝いの作業場・ワークフロー）みんなの決まり。変えるときは、この紙を先に直す。

## 3. 場面ごとの作り方

- **A・B（宇宙から）**：第2版の列島の場面（`film.py` の `build_global`・`atmos.py` の大気）を 4K 向けに作り直す。陸の色は地理院タイル（ランドサットのモザイク、
  近づく所は全国最新写真）。雪は標高で足す。夜の街の明かりは、国勢調査の人口からの明かり（`night_lights.py`）。日本の外（朝鮮半島・大陸）にも陸の色と明かりを入れる。
  海は太陽の照り返し。雲は、本物の衛星の雲の絵（NASA の毎日の全球画像など）に高さを持たせて置き、影を落とす。
  夜明けの線（幅のある帯）と大気の縁は物理の式で。
- **雲を抜ける**：白い雲の中で場面を替える。雲は奥行きのある白（一様な白い板にしない。雲のかたまりが手前から流れる）。
- **C（岩と雪）**：地形は 5m の標高、見せ場の近くは 1m の標高（国土地理院。吊尾根・梓川・東の尾根にある）。岩の 1〜30m の形は 1m の標高から取り、足りない所は写真から
  起こした岩・崖の立体と、割れ目の向きをそろえた 3 段の凹凸（約 10m・1m・0.1m）で足す（まず吊尾根の前後 200m と正面の岩壁）。岩・ガレ・雪の素材は 3 方向から貼り、3 つの大きさの
  柄を混ぜ、同じ柄を 1 画面に 2 回見せない（立体も素材も Poly Haven・ambientCG。CC0）。素材で作るのは道すじから 1,500m まで。航空写真は 2〜4m より大きい色むらだけに使う
  （影は撮影時の影で割る。夏の雪渓・小屋・登山道は塗り消す）。新雪は凹凸を足した後の形に積もらせる（棚とくぼみに残り、急な面は岩が出る）。石は見せ場の近くにだけ置く。
- **D（森と川）**：木は木の素材集（`trees/`）。どこに何が生えるかは、標高・傾き・向き・川からの距離・航空写真の色で決める（カラマツは林でまとまる。ダケカンバは
  森のふちと上。モミ・シラビソ・コメツガは北向きと上。ケショウヤナギは川原。2,500m から上はハイマツ。すき間・倒木・立ち枯れを入れる）。等間隔にしない。
  森の色は写真（緑の季節）でなく、木の種類の地図で作る。川は第3版の川筋をもとに、幅と州を写真に合わせ、浅い澄んだ水（底の石が見え、空と岸の木が映り、
  流れのさざ波）。朝もやは立体の薄い霧（川の上と谷の低い所）。
- **E・F・G（尾根越え・雲海・白鳥）**：雲海は赤富士の試しで作った立体の雲（高さの絵＋小さな入れ物に分ける）。遠くの山（八ヶ岳・富士山・南アルプス）は
  広い範囲の標高で形を作り、朝の空気で影絵にする。雲海だけは別に描いてよい（縦横 2 分の 1 より粗くしない）。白鳥は `swan_hero.py`。
- **空気と仕上げ**：遠くの青いかすみは、材質の中で距離を使って混ぜる（式は第2版 `atmos.py`・第3版 `post3.py`。後から足すと枝葉のふちに縁取りが出る）。
  谷のもやと光の筋は、本体と一緒に立体の霧として描く。色は AgX（最後に 1 回だけ）。動きのぶれは本物のシャッター（180°）。レンズのにじみ・粒・周辺の暗さは控えめに。
  太陽を正面に見る場面のフレアは、薄いにじみだけ（光の輪・筋は無し）。

## 4. 共通の決まり

- **座標**：東・北・上（m）。原点は河童橋（緯度 36.2490・経度 137.6380・標高 0）。高さは本当の標高（強調しない）。遠い所は地球の丸みの分だけ下げる。
  宇宙の場面は第2版の座標（km）を使ってよい（雲の中で替えるので、つなぎは向きと降りる角度だけ合わせる）。
- **時間**：24 コマ/秒・720 コマ（0〜719）。コマ f の時刻は f/24 秒。場面の切り替えは 5.45 秒（コマ 131 から山の場面）。つなぎ目はコマ 304 と 462。
- **光**：太陽の方位 115°（北から時計回り）・高さ 5°（山の場面を通して同じ）。空は Blender の空の計算（多重散乱）。色の扱いは AgX。
- **乱数**：木・石・羽など、ばらつきは全部、物の番号から決める（`np.random.default_rng((種類, 番号))`）。描く機械・コマの組が違っても同じ絵になること。
  カメラから見えるかどうかで乱数を引く順番が変わる作りにしない（第3版はこれで森がちらついた）。
- **細かさの段（LOD）**：0＝すぐ近く（20m 以内）、1＝近く（150m 以内）、2＝中（800m 以内）、3＝遠く（それより先。150〜300 面の立体の木）。段の切り替えは、
  全部のコマのカメラの位置から決める（コマの組ごとに変えない）。境は 1 本ごとにずらす。地面の細かい凹凸の割り方も同じに固定する。
- **置き場**：`scripts/pc-opening4/`。作業の材料は `work/`（git に入れない）。確かめの絵は `review/<名前>/`（JPEG・横 1600px まで・1 枚 400KB まで）。
- **道具**：Blender 5.3（Python の bpy）・Cycles・CPU。お金のかかる物は使わない（Runpod は残り 5.21 ドルの範囲だけ）。素材とデータは、使ってよい条件を元のページで確かめ、
  `ASSETS.md` に出所を書く。Google の地図・画像は使わない。

### 素材集に求めること（場面を組む側との約束）

- 木：`trees/library.py` の `build_library(species, variants, lods)` が、名前 → 1 本ぶんの物（幹・枝・葉をまとめた 1 つのメッシュ。原点は根元・上が +Z・単位 m・
  本当の大きさ）を返す。名前は `<種類>-<番号>-lod<段>`。種類：`larch`（カラマツ）・`birch`（ダケカンバ・シラカンバ）・`fir`（シラビソ・モミ・トウヒ・コメツガ）・
  `willow`（ケショウヤナギ）・`pumila`（ハイマツ）・`snag`（立ち枯れ・倒木）・`under`（ササ・シダ・草・低木）。
- 白鳥：`swan_hero.make_hero(name, phase0)` と `set_pose(sw, phase)`。原点は体の真ん中・前が +Y・単位 m。

## 5. 描く計画

- 測ったこと（2026-11-24。この作業場＝CPU 4 つ）：第3版の森の場面を 3840×2160・64 回で 1 コマ 50.8 分、メモリ 7.6GB（GitHub の機械 16GB に入る）。
- 見込み：山の場面 589 コマ × 平均 40〜60 分 ≒ 390〜590 台・時間。宇宙の場面 131 コマは軽い（1 コマ 5〜10 分）。元は軽い第3版。本番は 2〜4 倍もありうる。
- 先に測る：いちばん重いコマ（15.0 秒。森＋川＋もや）を仮の素材で 64〜256 回描き、時間とメモリ（12GB 以下）を測る。GPU（Runpod。0.5 ドル以内）でも測る。
  描き直し 3 割も見込む。影の谷は 64 回では粒が残る見込み。192〜256 回＋色と向きの下絵を使うノイズ取りを基準にし、6 章 4 で決める。
- 描く機械：GitHub Actions（無料。同時に約 20 台・1 回 6 時間まで）で 1〜1.5 日。長い描画に使ってよいか、規約の原本を先に確かめる。足りない所だけ Runpod の GPU
  （残り 5.21 ドルの範囲）。手伝いのクラウドの作業場は Claude の使用量を使うので、描くだけの仕事には使わない。
- 層を分ける：雲海だけ別に描く。朝もやは本体と一緒。白鳥も別の層（背景は透明）。
- 中間の絵は、光の量をそのまま持つ EXR（PNG は使わない）。4K の前に、全編を 1920×1080 で描いて動きを確かめる。最後に AV1（10 ビット）4K（20〜30 メガビット/秒）・
  1440p・1080p と、HEVC・H.264 を作る。

## 6. 確かめ方

1. 影と道すじ：標高から影の地図を作り、道すじに重ねる。`route.py` が全コマを自動で検査する（1 コマの移動＝速さ ÷ 24・流れる速さ・曲がる速さ）。下書きの動画で、
   つまらない所・映るはずの物が入らない所・つなぎ目が分かる所を直す。止め絵より先に持ち主へ送り、長さ（30 秒）・つなぎ目・飛び方の OK をもらう。
2. 素材：木・岩・白鳥・雲それぞれの確かめの絵を、厳しい目（作り物に見える所を探す役）に見せ、同じ太陽の高さ・同じ距離の実物の写真と横に並べ、見分けがつかなくなるまで直す。森は上から見下ろした絵で見る。
3. 大事な止め絵 6 枚を 4K で：A（1.8 秒・夜明けの線が日本を横切る）、C2（10.2 秒・吊尾根を越える瞬間）、D2a（14.6 秒・カラマツの梢）、D2b（16.6 秒・梓川）、
   E（22.8 秒・尾根を越えて朝日と雲海）、F（25.0 秒・白鳥）。持ち主に送る。
4. 動く試し：続き 48 コマを 2 本、本番の設定で描く（D2 の 14.5〜16.5 秒、F の 24.5〜26.5 秒）。配る形式に圧縮し、4K の画面で等倍で見る。
   合格＝粒・ゆらぎ・色の段・つぶれが見えない。
5. 動画：同じコマを 2 つの組で描いて同じ絵になること（ちらつきの検査）。全部のコマがそろうこと。できた動画も 4K の画面で等倍で見る。
6. アプリ：`lib/app/opening.ts`（長さ 30.0 秒・ロゴ 24.8 秒から・消えるのは 29.2〜29.9 秒・4K の映像を足す）、出典の表示、`npm run lint`・`typecheck`・`test`。

## 7. 危ない所と手当て

| 危ない所 | 手当て（先に確かめること） |
|---|---|
| 近くの岩・地面がぼやけ、岩らしい形が無い | 見せ場①の止め絵を最初に作る。1m の標高・岩の立体・3 段の凹凸で作り、本物の穂高の岩稜の写真と並べる |
| 森が同じ木の繰り返しに見える | 木の素材集の「森の試し」（300 本以上・混ぜて植える）で、同じ木が見つからないことを確かめる |
| 谷底が影で、暗くのっぺり見える | 明るさを 2 段上げ、朝もや・水に映る空・川原や草の霜で明るさを作る。見せ場②の止め絵で確かめる |
| 立体の雲が重い | 雲海だけ別に描く。遠い雲海は高さの絵の面にして、近くだけ立体にする |
| 手分けして描くとちらつく | 乱数は物の番号から。段はすべてのコマから決める。同じコマを 2 つの組で描いて比べる |
| Claude の使用量の上限で作業が止まる | 仕事を小さく分け、区切りごとにファイルに残す（各担当は `NOTES.md` に進み具合を書く）。止まっても続きからやり直せるようにする |
