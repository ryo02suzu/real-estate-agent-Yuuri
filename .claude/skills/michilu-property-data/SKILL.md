# 不動産調査データの信頼性

## 基本方針
- `README.md`、`docs/features.md`、`lib/roadmap/` と対象データの出典・更新フローを確認する。
- MICHILUは不動産営業が「1物件」を調べるための情報整理ツール。公式情報の参照先と検証状態を明確にする。接道義務・再建築可否・法令適合性を自動で断定しない。

## 実装チェック
1. **データと推論を区別**：API・地図に記載がある事実／独自計算・推定／人が確認した結果を別々に示す。
2. **不明を「無し」にしない**：データが無い、未調査、読取失敗、対象外、確認済みを適切に区別する。区域外の判定にもデータ範囲と時点を確認する。
3. **出典を残す**：提供元、資料名、URL、基準日・更新日、対応範囲、利用条件を可能な限り記録する。法務局・自治体・国の資料の優先順位は対象情報によって判断する。
4. **道路**：近くの道路線の検出と、建築基準法上の前面道路・接道適合の判断は別。自治体公式図と窓口確認の導線を残す。
5. **都市計画・ハザード**：国の参考データと重要事項説明に利用すべき自治体資料を区別する。建ぺい率・容積率の数値のみから建築可能規模を確定しない。
6. **地番・筆・建物・地価**：住所と地番を混同しない。推定筆界・推定位置・建物属性・標準地価格を登記上の確定情報や対象物件の査定額として表示しない。
7. **更新と検証**：既存のデータ生成スクリプト、`.github/workflows/`、対象の`*.test.ts`を確認する。取得先変更時は失敗・データ空・境界・更新時点のケースも追加する。

## 完了条件
- 正確性・最新性を検証できていない事項は未確認と記す。
- 必要なら公式出典を再確認する。変更で増えた項目は `docs/features.md` に反映する。
- テスト、型、lintの実行結果と残る手動確認箇所を報告する。
