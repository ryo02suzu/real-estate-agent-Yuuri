# MICHILU回帰テストと品質ゲート

## 着手前
- `CLAUDE.md`、`AGENTS.md`、`package.json`、対象の既存テストを読む。
- 修正前後の動作・合格条件を、1物件の住所検索という中心導線から具体化する。
- Next.js APIはリポジトリのバージョンと、利用可能なら `node_modules/next/dist/docs/` の文書を優先する。

## 必須の検証
1. 変更に対応したユニットテスト・境界値テストを追加または更新する。
2. 原則 `npm run lint`、`npm run typecheck`、`npm test` を実施。必要に応じて `npm run build`。ネット接続を必要とするライブテストは通常のテストと区別する。
3. UI変更はモバイル・PCを検証。PCの表示不変、低い画面、読み込み待ち、失敗時、同一住所再検索、入力・履歴、キーボード操作を重点確認。
4. 地図変更は地図座標、レイヤー・凡例・帰属表示、WebGL代替、表示性能を確認。
5. 情報変更は「データなし」「未確認」「推定」「失敗」「確認済み」の混同、法的断定、更新日時、外部API異常を確認。

## 報告形式
- 変更内容：何がどう変わったか
- 検証：実行したコマンドと結果、画面確認をしたか
- リスク：未解決の問題、実行できなかった検証、外部の確認が必要なこと

**禁止**：テスト未実施を「成功」、コード読解だけで「画面確認済み」、UIモックを「実測」と記載すること。
