# MICHILU UI/UX

## 最初に読む
- `CLAUDE.md` と `docs/features.md`、変更対象の `components/`、`app/globals.css` を確認する。
- 既存の利用シナリオを言語化する：対象物件を既に知っている不動産仲介営業が、住所・地番・地図上の地点から調査する。物件探し・架電管理に変えない。

## デザイン原則
1. **使いやすさ優先の上質さ**：Apple純正アプリのような滑らかさ、情報の階層、余白、操作の一貫性。見栄えのために調査結果を隠さない。
2. **モバイル最優先**：iPhoneサイズ、背の低い画面、セーフエリア、片手での操作、文字の折返し、タッチ領域、ソフトウェアキーボード表示時を確認する。
3. **PCの既存表示を保護**：`CLAUDE.md` のPC表示不変ルールを守る。PCの見た目に変更が必要なら依頼範囲と明示的な承認を確認する。
4. **検索中心**：ヘッダー、検索欄、最近の検索・履歴、調査結果への導線を優先し、依頼のない物件探索・架電管理など別用途の機能を足さない。
5. **未実装の構想は勝手に実装しない**：「地球 → 日本 → 物件」の連続ズームや時間帯・季節に連動する都市演出は、現行コードに実装されていない将来構想。通常のUI修正・レビューでは作業対象に含めず、独立したIssueなどで明示的に依頼された場合にのみ検討・実装する。依頼された場合もデータの正確性、画像ライセンス、端末性能を確認する。
6. **運用できる品質**：loading / empty / unavailable / error / confirmed を混同しない。`prefers-reduced-motion`、キーボード操作、見えるフォーカス、十分なコントラストを考慮する。

## 変更手順
1. 現状の画面・コンポーネント・ブレークポイントと依頼の差分を整理する。
2. 新しい依存や画像を増やす前に既存のTailwind CSS・Reactコンポーネント・素材を再利用する。
3. 住所検索から結果表示まで、入力値・状態・戻る操作・履歴が維持されるか確認する。
4. 見た目を変更したらモバイルとPC両方を確認する。ブラウザが無い場合は「実画面未確認」と明記し、スクリーンショットを見たことにしない。
5. `npm run lint`、`npm run typecheck`、`npm test` を実行し、機能が変わった場合は `docs/features.md` を更新する。実行できない確認は未実施として報告する。
